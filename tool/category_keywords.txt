VYAYA - CATEGORY KEYWORDS
(The app's copy lives in lib/services/capture/merchant_categorizer.dart; this file is the readable version.)
=========================================================================

How to read this file
- EXISTING : already in the app today (lib/services/capture/merchant_categorizer.dart)
- NEW      : proposed additions, not in the app yet
- MOVED    : already in the app, but proposed to go under a different group
- REMOVE   : already in the app, proposed to drop (too generic, causes wrong matches)

Matching rules (proposed)
- Case, spaces, dots, dashes and underscores are ignored:
  "Burger King", "BURGERKING", "burger_king", "burgerking@ybl" all match "burger king".
- Longer names win over shorter ones: "swiggy instamart" (Groceries) beats "swiggy" (Food),
  "amazon fresh" (Groceries) beats "amazon" (Shopping), "jiomart" beats "jio".
- Names of 4 letters or fewer must be a whole word: "ola" won't match "cola", "kfc" won't
  match inside another word.
- Longer names must be the whole word (plus "s"/"es", e.g. "medicals"), or start a word
  followed by 3+ letters (UPI handles like "zomatoonline"). So first names like "Bhavana"
  don't match "bhavan". Brands that are also common first names (Nandini, Yashoda,
  Aakash...) only match with a second word ("nandini milk", "yashoda hospital").
- Your own choice for a payee always wins over this list.
- This list is matched against the PAYEE name only (e.g. "BURGER KING", "swiggy@icici").
  A short separate list of message words (electricity, EMI, recharge, rent, insurance,
  fees...) is checked in the rest of the SMS only when the payee didn't match, so words
  like "unlimited" or "auto-debit" in an SMS can't pick a category.

Each group says which of YOUR categories it goes to:
  "Goes to"  = the category it uses (first one of these that exists in your categories)
  "If none"  = what Vyaya offers to create when none of them exist

NOT MATCHED ON PURPOSE
-------------------------------------------------------------------------

  category from what you picked for them before.
  Payment apps on their own (paytm, phonepe, google pay, gpay, bhim, mobikwik, cred)
  don't decide the category; the payee after them does ("Paytm - Zomato" -> Food).
  Banks (hdfc, sbi, icici...) are never used as a payee.

HOW SHOPS SHOW UP IN BANK SMS / UPI  (NEW - so the list above still works)
=========================================================================
Banks often print the company's legal name, a payment-gateway prefix, or a
UPI handle instead of the brand. Vyaya cleans these first, then matches.

A) Payment-gateway prefixes are removed before matching (NEW)
   "PAYU*SWIGGY", "RAZ*ZEPTO", "RAZORPAY SWIGGY", "BILLDESK*TATAPOWER",
   "CCAVENUE-IRCTC", "PAYTM*ZOMATO", "PHONEPE*UBER", "CASHFREE*NUTRABAY",
   "JUSPAY-", "EASEBUZZ", "INSTAMOJO", "PINELABS", "PG-", "ECOM-", "POS "
     -> matched as swiggy / zepto / tata power / irctc / zomato / uber / nutrabay

B) UPI handles: the part before "@" is used, dots/digits trimmed (EXISTING idea, improved)
   swiggy.stores@axb, swiggyupi@axisbank      -> swiggy      -> Food

   bigbasket.rzp@icici                         -> bigbasket   -> Groceries

   Handles that say nothing (paytmqr..., Q123456@ybl, BHARATPE.xxx@unitype,

   Education:     school, college, academy, institute, coaching, tuition,
                  classes, university, library

E) Words NOT used on their own (too vague): traders, enterprises, services,
   solutions, agency, corporation, industries, company, store, shop, mart, mall.
